# lint 化の観点

人間が AI に出した修正指示のうち、リンターなどの機械判定に任せられるものを見つけて提案する。
AGENTS.md に書いて AI に守らせているルールを、リンターで確実に止められるようにするのが狙い。

## 手順

1. observation を、中身が同じ指示ごとにまとめる。言い回しが違っても、求めていることが同じなら同じ指示として扱う。
2. 作業フォルダがあれば、AGENTS.md と CLAUDE.md を読み、それぞれの指示に対応するルールを探す。ルールの頭に `[G-012]` のような guidance ID があれば、その ID を使う。
3. 作業フォルダのリンターの設定（package.json、eslint.config.*、.eslintrc*、.oxlintrc.json、biome.json、.stylelintrc* など）を読み、どのリンターをどんな設定で使っているかを確かめる。
4. 指示ごとに、次の 3 つのどれに当たるかを判定する。
   - 既存ルールで止められる：使っているリンター、または追加しやすいプラグインに、そのまま使えるルールがある
   - 自作ルールなら止められる：既存のルールはないが、構文や import の形から機械的に判定できる
   - 機械判定できない：文脈や意図の判断が要る
5. 観点の設定の `threshold`（なければ 3）件以上の observation がある指示を、1 件ずつ提案にする。
6. `threshold` に届かない指示は、まとめて 1 件の提案「様子を見る指示」にし、指示と observation の id を一覧で載せる。

ルール名は、存在を確かめられたものだけを書く。
うろ覚えのルール名は書かず、「自作ルールなら止められる」として扱い、既存のルールがあるかもしれないと添える。
リンターの設定がすでにそのルールを有効にしているなら、提案にせず、そのことを「様子を見る指示」の一覧に書く。

## 提案の書き方

- title：「〜を lint で止める」のように、何を止めるかが分かる見出しにする
- observation_ids：その指示にまとめた observation の id をすべて入れる
- change：次の順で書く
  - 指示の中身（1 文）と、件数
  - 対応する guidance（`[G-012]` と文面。見つからなければ「AGENTS.md に対応するルールなし」）
  - 判定（上の 3 つのどれか）と、その理由
  - 既存ルールで止められるなら、ルール名と設定例。自作ルールなら、何を見てどう判定するか。機械判定できないなら、代わりに AGENTS.md の書き方で直せることがあるか

ローカルで使う段階なので、ファイルは書き換えず、提案を書くところまでで止める。
