# lint 化の観点

人間が AI に出した修正指示のうち、リンターなどの機械判定に任せられるものを見つけて提案する。
AGENTS.md に書いて AI に守らせているルールを、リンターで確実に止められるようにするのが狙い。

## 手順

observation は、aRefine が中身の同じ指示ごとに「指示のまとまり」へ振り分けてから渡す。件数はまとまりごとに、実行をまたいで数えている。

1. 作業フォルダがあれば、AGENTS.md と CLAUDE.md を読み、まとまりごとに対応するルールを探す。ルールの頭に `[G-012]` のような guidance ID があれば、その ID を使う。
2. 作業フォルダのリンターの設定（package.json、eslint.config.*、.eslintrc*、.oxlintrc.json、biome.json、.stylelintrc* など）を読み、どのリンターをどんな設定で使っているかを確かめる。リンターの version は `node_modules/<パッケージ名>/package.json` の version で確かめる。
3. 次のどれかに当たるまとまりだけを判定する。当たらないまとまりは、判定も提案もしない。
   - まだ判定していないまとまりで、件数（count）が観点の設定の `threshold`（なければ 3）以上
   - まだ判定していないまとまりで、今回入った observation に `stated_as_rule` が true のものがある。人がルールとして言い切った指示は、1 回しか出ていなくても判定する
   - まだ判定していないまとまりで、今回入った observation に `risk_kind` が null でないものがある。取り返しのつかない操作や情報の漏れにつながる指示は、1 回しか出ていなくても判定する
   - 判定済みのまとまりで、件数が `count_at_judgment` から観点の設定の `rejudge_after`（なければ 3）件以上増えた
   - 判定済みのまとまりで、`state.linters` に残したリンターの version が、いまの version と違う
4. 判定するまとまりごとに、次の 3 つのどれに当たるかを決める。
   - `existing-rule`（既存ルールで止められる）：使っているリンター、または追加しやすいプラグインに、そのまま使えるルールがある
   - `custom-rule`（自作ルールなら止められる）：既存のルールはないが、構文や import の形から機械的に判定できる
   - `not-mechanizable`（機械判定できない）：文脈や意図の判断が要る
5. 判定したまとまりは judgments に入れる。
   - state は `{ "result": 上の 3 つのどれか, "reason": 判定の理由, "rule": "<リンター名>: <ルール名>" または null, "linters": { "<リンター名>": "<version>" } }` の形にする
   - trackable は、`existing-rule` で、いまのリンターの設定ではそのルールがまだ有効になっていないときだけ true にする。`custom-rule` と `not-mechanizable` は false にする
6. 判定したまとまりは、1 件ずつ提案にする。機械判定できないまとまりも、AGENTS.md に書き足す・書き直す提案として出す。ただし、リンターの設定がすでにそのルールを有効にしているなら、提案にしない。
7. trackable が true で resolved_at がないまとまりは、`state.rule` のルールがいまのリンターの設定で有効になっているかを確かめる。有効になっていれば、その id を resolved に入れる。
8. 今回 observation が入ったが、まだ一度も判定していないまとまりは、まとめて 1 件の提案「様子を見る指示」にする。判定済みで今回判定し直さなかったまとまりは載せない。まとまりの id・1 文・件数を一覧で載せ、groups にはそれらの id を入れる。当たるまとまりがなければ出さない。

ルール名は、存在を確かめられたものだけを書く。
うろ覚えのルール名は書かず、「自作ルールなら止められる」として扱い、既存のルールがあるかもしれないと添える。

## 提案の書き方

- title：何を止めるかが分かる見出しにする。lint で止めるなら「〜を lint で止める」、AGENTS.md で扱うなら「〜を AGENTS.md に書く」
- groups：その提案の根拠にしたまとまりの id
- change：次の順で書く
  - 指示の中身（1 文）と、これまでの件数。件数が `threshold` に届かず、ルールとして言い切られたことや、`risk_kind` が付いていたことで提案にしたなら、そう書く。`risk_kind` なら、どの種類（データや履歴が消える・書き換わる／秘密情報や外に出せない情報が漏れる／手元の外に反映・送信される）に当たったかも書く。判定し直したなら、その理由（件数が増えた、リンターの version が変わった）も書く
  - 対応する guidance（`[G-012]` と文面。見つからなければ「AGENTS.md に対応するルールなし」）
  - 判定（上の 3 つのどれか）と、その理由
  - 既存ルールで止められるなら、ルール名と設定例。自作ルールなら、何を見てどう判定するか。機械判定できないなら、AGENTS.md に書き足す文面か、いまのルールの書き直し案

ローカルで使う段階なので、ファイルは書き換えず、提案を書くところまでで止める。
